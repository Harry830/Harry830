<sub>§ &nbsp; **WHAT I CARE ABOUT**</sub>

## What I care about

> ### `i.` &nbsp; Backend contracts that are obvious
>
> If someone has to read the source to figure out what an endpoint does, the contract is wrong. I lean on OpenAPI, Zod, and clear request/response shapes so the boundary is the documentation.

> ### `ii.` &nbsp; UIs that are usable, not just shiny
>
> Motion is fine. Motion hiding a confusing flow is not. The surface should explain itself before anyone has to ask.

> ### `iii.` &nbsp; Docs and tests so projects survive a handoff
>
> Future me counts as a different person. README, env example, structured logs, and tests at the seams — that's the minimum bar for anything I keep working on.

> ### `iv.` &nbsp; Things that run outside localhost
>
> Most of what I build is deployed and reachable. I've been spending time on GSU's HPC / ARCTIC environment for heavier workloads lately — making sure the systems hold up off my laptop is part of the work.
